# Animal Information Hub UK — image library

The published website uses **assets/images/** as its organised, optimised image library. Keep published image files in the relevant category folder and reference them with the full project path:

`/SAISAnimalInformationHubUK/assets/images/<category>/<filename>.webp`

## Published folders

- `animals/` — species landing-page photographs (dog, cat, chicken, horse, rabbit, rodents, reptile/exotic and wildlife).
- `awards/` — awards and recognition marks.
- `books/` — book-cover artwork and the recommended-books visual.
- `branding/` — supplied Hub branding artwork.
- `cats/` — feline-specific guides and resources.
- `dogs/` — dog training, behaviour, food, travel and health graphics.
- `general/` — shared animal-care, enrichment, safety and rescue visuals.
- `lost-found/` — lost-and-found advice graphics.
- `other/` — specialist identification and reference graphics.
- `partners/` — partner, organisation and specialist resource logos.
- `wildlife/` — wildlife-specific guides, including adder-bite information.

## Original supplied files

`assets/image-library/` is retained as the original supplied-image/reference archive. Do not delete it when updating the published library. `assets/image-library/image-placement-manifest.json` records the intended placement of labelled source images. Contact sheets in that folder are reference material and must not be displayed as page artwork.

## Image publishing rules

1. Use descriptive, meaningful alt text for informative images; use empty alt text only for decorative images.
2. Preserve aspect ratio. Use `object-fit:contain` for logos, diagrams and book covers; use `cover` only for photographic crops that remain accurate.
3. Keep file names descriptive and lowercase. Prefer compressed WebP for published raster images.
4. Do not hotlink images from third-party websites. Keep approved local copies in this library.
5. Record the creator/source, licence or written permission, date checked and any attribution required before publishing third-party artwork, logos or book covers.
6. Never treat a supplied filename, visible logo or source credit as proof of reuse permission.

## Rights register status

The repository does not currently contain documentary permission records for every supplied third-party graphic, logo and book cover. The owner must retain the original permission, licence or written confirmation for those assets. This register deliberately does not claim permissions that have not been evidenced.
